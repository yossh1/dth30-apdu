# FINDINGS 要約 — DT-H30/U2 カード汎用化で確定した事実

調査（2026-11）の記録から、技術的に再利用価値のある確定事実を抜粋した要約です。
証拠ログ等の生データは公開していません。設計経緯の詳細は docs/ の各文書を参照してください。

## 対象と結論

- BUFFALO DT-H30/U2（USB、VID 0x0411 / PID 0x0128、地上デジタル ISDB-T 専用）の
  内蔵 B-CAS スロットを、ホストから汎用カードリーダーとして駆動できる経路が
  あるかを確定する調査。
- 結論: 経路は2つ実証できた。(1) 純正ファームへの揮発パッチ（Mode Q）、
  (2) 互換 CFW（DTH10-series-driver）への APDU コマンド新設（本 repo の driver-apdu）。

## 純正ファームウェアの解析（静的解析＋実機）

- ダウンロードイメージには署名・チェックサム等の検証がない。データ域・コード域
  それぞれ1バイト改変したイメージが純正と同一にブート・機能することを
  A/B/A 実験で確認した（起動は毎回ホストからイメージを送る方式で、恒久書換えは不要）。
- カード層の実ハードは内蔵 ISO7816 UART（MMR 0x1020 台＋GPIO 0x1084–0x1090）。
- カードジョブの投入口は単一の内部 API（0xA0121700）に集約される。前提は
  T=1 状態構造体のフラグ（ATR 解析済みビット）。リクエストのペイロード上限は
  構造的に 0x80 バイト（制御フィールドが +0x80 から固定のため）。
- 純正のホストプロトコル（RPCI）に汎用 APDU の素通し経路は存在しない。
  カード情報（ID・契約状態・EMM）は push 型の完了通知でのみホストへ返る設計。
- 純正 Windows ドライバが発行するコマンド（Func）の集合は
  {0x08, 0x09, 0x0A, 0x0B, 0x0D, 0x10, 0x12, 0x13, 0x14, 0x15, 0x16, 0x18, 0x19, 0x1A, 0x1B}
  で、Func 0x04 は含まれない（未使用）。Mode Q はこの未使用スロットをフック先に使った。
- ファームイメージ内には 6,596 バイトのコードケーブ（file 0x1E238）が存在し、
  実機で読み書き・実行に使えることを確認した。
- DDR アクセスのアパーチャ規約: MMR 0x43C の field で 1MB 単位のページを選択
  （field 0 は共有 RAM／メールボックス）。ホストから到達できるのは field 0〜63
  （共有 64KB＋63MB）で、64 以降はそのミラーだった。
- カード状態を追う state dword（DDR field 2 +0x37FF0）は
  0=カードなし / 1=カードあり・セッションなし / 3=セッション開始後 と遷移する。
  隣接する +0x37FD8 はカード挿入エピソードごとに生成され、抜去とセッション開始で
  消える値だった。
- 起動リプレイの読み取りミスマッチ5件は、カードの有無ではなく
  「同一電源サイクル内の再ブート」と相関する（初回ブートでは 0 件）。

## Mode Q（純正ファーム＋揮発パッチ）

- 未使用の Func 0x04 のスタブをトランポリンに差し替え、コードケーブに置いた
  自作ハンドラから純正のジョブ投入 API を呼ぶことで、ホストから任意 APDU
  （1件ずつ、最大 0x80 バイト）をカードへ送れることを実機で実証した。
- テスト APDU（INITIAL_SETTING）で 61 バイト・SW 9000 の応答を回収し、
  3回連続発行でも安定動作した。パッチは DDR 上の揮発変更のみで、電源断で純正に戻る。
- 実装上の要点: 実行イメージはドライバ同梱イメージと別リンクの「ストリーム」
  ビルドであり、全シンボルをストリーム側で実測し直す必要があった。また、
  ハンドラが渡す ctx は KSEG1 正規形に直さないと、純正側の teardown チェック
  （assert）でカードタスクが停止する。

## 互換 CFW への APDU 拡張（driver-apdu）

- DTH10-series-driver（MIT。互換 FW は Rust ソースからのクリーンルーム生成で、
  純正 blob を含まない）に、ホストプロトコルの新コマンド 28（APDU 交換）を追加した。
  - 送信 APDU は最大 60 バイト、送受信合計は最大 127 バイト（FW 内カウンタの制約）。
  - ECM と同じジョブキューに直列化するため、視聴（復号）中の APDU 交換が可能で、
    交換後も復号は維持される。
  - カードの電源断・状態消去の経路では、保留中の APDU が必ず完了コード付きで
    終わる（無言消失しない）。
  - ATR は従来 FW が保持していなかったため、保持＋読み出し（QUERY）を新設した。
- 実機検証: INITIAL_SETTING の応答が Mode Q で得た応答と完全一致
  （61 バイト・SW 9000、SHA-256 指紋一致）。serve 常駐化（v2）により、
  ストリーム配信中でも Unix ソケット経由で APDU 交換できる。
- 速度の実測比較（選局→復号済み TS）: 互換 CFW 方式は約 4 秒。純正リプレイ
  ブート方式は約 86 秒で、出力はスクランブルのまま（復号は別段）。
- カードを抜いて再挿入した場合、同一セッション内では APDU 受付は自動復帰しない。
  ホスト主導の新規セッション（カードリセット要求）で復帰する（仕様として確定）。
- INITIAL_SETTING の応答はカード内部状態の更新で時間変化する。応答の同一性を
  指紋で照合する場合は、同時期のベースラインと比較すること。

## vicc（PC/SC 橋渡し）

- vpcd＋自作ブリッジにより、DT-H30 のカードが標準 PC/SC リーダー（仮想
  リーダー）として見え、一般の PC/SC クライアントから APDU を送れることを
  実機で確認した。視聴ストリームとの共存、ホスト再起動後の自動復帰も確認済み。
- 旧ブリッジの詰まり機構: カード不在時に長さ 0 の ATR 応答を返すと、vpcd 側が
  0 バイト受信待ちでブロックし、読み取りスレッドがロックを握ったまま停止して
  後続の全 Transmit が凍結した。vsmartcard の設計では「接続していること自体が
  カード在席」であり、0 バイト ATR はイジェクト相当の扱いになる。
- 修正方式: 在席をポーリングし、カードがある間だけ vpcd との接続を張る。
  不在が一定時間（約8秒）続いたら切断して REMOVED を伝播させる。実機では
  抜去から約18秒で REMOVED が PC/SC 層に届き、再挿入では同一セッションの
  まま自動復帰した。
