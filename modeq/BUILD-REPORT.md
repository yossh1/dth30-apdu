# Mode Q ハンドラ（バリアント B）机上ビルド報告 — 2026-11-23（検証係の差し戻し対応済み・最終版）

調査員が `modeq_handler.asm`（設計＋stream 実測シンボル）を作成した後、ビルドスクリプトの書き込みが調査員側の安全ポリシーで停止したため、親側でビルド工程のみを引き継いで実施した。実機には触れていない。

## 調査員の重要な発見（前提の訂正）
hw 系列 replay で実際に起動するのは file イメージではなく、記録された純正ドライバの **stream（別リンクのビルド）**。file 側アドレスのままでは動かないため、全シンボルを stream 側で実測し直した（署名マッチ＋逆アセンブル照合）:
- submit 0xA0121700（シフト0）/ alloc 0xA0154854 / free 0xA0154C1C / worker exit 0xA015373C（各 −0x80）/ memcpy 0xA01FE680（−0x220、stream スタブ自身の jal 先とも一致）
- $gp(stream) 0x8023DBC0、state-ptr global 0x80237050、pool-ptr global 0x8023700C、ctx アンカ **0x80253308**（file の 0x80255158 ではない）

## 検証係の差し戻し（1件）と対応
- **$v1 プリセット欠落**: ワーカー共通出口 0xA015373C は $v0==0 のときだけ slot+0x10 に 1 を書き、それ以外は $v1 をそのまま書く。純正 case は出口への分岐の遅延スロットで `addiu $v1,$zero,2` を置くのが規約だが、ハンドラは $v1 を書いておらず、拒否パスで slot+0x10 にディスパッチャの残り値 0x801FF180 が書かれる欠陥があった。→ mq_exit の遅延スロットを nop から `addiu $v1,$zero,2` に変更（asm 側に根拠コメント付き）。
- あわせて軽微2件も asm 冒頭に反映: エラーコード対応表が APDU-DESIGN §6 とずれる点の明記、キューパージ時に PEND が busy のまま残る v1 制限の追記。

## ビルド時の注意（Keystone の癖、対処済み）
- **`.set noreorder` が必須**: 無しだと Keystone が分岐ごとに自前の nop を挿入し（ハンドラで +19 命令）、ソースの遅延スロット命令が遅延スロットの外へ押し出される。特に $v1 の addiu が実行不能位置に落ちるため、初回ビルド（720 B）はこの点で実質的に誤りだった（本報告の最終版で置換済み）
- `addiu` の即値が 0x8000 以上だと $at 経由の2命令に展開される → 符号付き即値（負数）で置換して1命令化
- 末尾分岐の後に余分な nop が付く → トランポリンは先頭 8 B を採用し、j ワードを手計算エンコーディングと照合

## 追記（2026-11-23、実機検証1回目の失敗を受けた修正版）
